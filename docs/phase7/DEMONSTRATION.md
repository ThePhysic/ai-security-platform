# Controlled flagship demonstration

Use persisted controlled records; real and hosted admission remain disabled by default.
No private repository, external service, live model, public deployment or target execution
is required. Begin with [the local runbook](RUNBOOK.md).

## Ten-minute interview walkthrough

1. Connect the dashboard at `http://127.0.0.1:18082` using the existing operator bearer
   privately. The credential field clears; reload/disconnect requires authentication again.
2. Open project `52e38442-7103-47a3-aa8e-371359aa97ef`, the Phase 7 controlled demonstration.
   Select genuine scan `416718ed-b4b3-4f08-ba07-2f280a199697`.
3. Show the authorized immutable snapshot identity and scanner provenance. This run used
   maintained source-only Python/JavaScript/dependency/Docker/IaC/CI fixtures plus a synthetic
   credential. Nothing was executed or installed from that source.
4. Show **86 genuine normalized scanner observations**: eight Semgrep and 78 Trivy in
   this fixture. They are alerts requiring review, not 86 independently confirmed exploitable
   vulnerabilities. Expand per-scanner coverage, rules/image/DB provenance and limitations.
5. Open finding `d782043f-f12d-43f5-bc3a-ed9a099d5fb8` (Python eval).
   The explicit deterministic investigation is `2debeba4-b69d-4669-ace3-d68a56bdfd85`.
   It retrieved finding, source, rule and coverage evidence, then produced `needs_review`
   with `evidence_supported`. Show snapshot/line citations, confidence and advisory guidance.
6. Contrast the unsupported-family investigation
   `98fa8a54-437d-4858-b6e5-79d587f3b5ed`, which abstained. Explain that the offline provider
   is a limited deterministic baseline, not live hosted reasoning or independent discovery.
7. Show two explicit human revisions and scoped feedback. A stale expected revision was
   rejected with 409. For a live review demonstration, choose a separate unreviewed controlled
   finding; explain the confirmation and conflict behavior before saving. No advice changes
   source or a human disposition automatically.
8. Query history with the CLI and inspect the JSON/SARIF exports generated by the helper.
   Default required scanners completed and the HIGH threshold failed, so exit was **1**.
   A separate synthetic diagnostic scan completed but could not satisfy required real
   scanners, so default policy returned **2**. A policy pass is never a security guarantee.
9. Explain the recorded recovery: with a diagnostic scan durably queued and its worker
   stopped, actual API/DB containers restarted without deleting volumes; the queued resource
   survived, completed after worker startup, and the genuine report remained unchanged.
10. Show the private matched-backup contract and sanitized restore evidence. Eighteen table
    fingerprints and associated source identities matched; a real interrupted PostgreSQL
    restore rolled back and retried. Never open the backup, credential file or full snapshots
    in a screen share.

The dashboard reports loaded pages/selected findings only, not global totals. Selecting a
different finding discards unsaved notes; same-scan background refresh preserves the draft.
Synthetic diagnostics stay explicitly separate from real scanner observations.

## Reproduce the controlled workflow

```powershell
uv run --frozen python -m scripts.validate_phase7_demo
```

Prerequisites: validated Windows/Docker Desktop boundary, retained approved scanner images
and matching non-stale offline DB, normal local API/worker/triage services, and available
source/report quotas. Stop any other host launcher. The helper temporarily enables real
admission only for the maintained inert fixture and restores disabled admission in `finally`.
It creates and retains new project/source/scan/triage/review records and two export files.
It does not reset old history. Repeated runs consume finite quotas; stop on exhaustion.
Actual hosted model execution remains disabled throughout.

[demo-evidence.json](demo-evidence.json) records controlled IDs, commands, scanner provenance,
revision history, policy outcomes and eight end-to-end checks. Source bytes, raw credentials,
screenshots and private backups are excluded. The full PostgreSQL regression supplies the
additional 25 scan and five triage crash/fencing experiments; the small demo is not presented
as a replacement for those tests.

## Honest talking points

- Authorization is enforced by application code independently of model output. The agent
  has no shell, arbitrary URL, Docker, write or remediation tool.
- Queue compute can repeat. Only a current token/generation/expiry owner can atomically
  publish authoritative findings, states and completion events.
- Scanner execution success, actual coverage, triage confidence and human disposition are
  separate facts. Missing evidence never becomes a clean result.
- Citation identity is checked separately from semantic support. A13 demonstrates that
  unsupported advice can still be accepted as advisory text; humans must verify it.
- The frozen benchmark has 28 fixtures, 14 held out, 16 adversarial cases and explicit
  unsupported/incomplete/ungraded denominators. It supports bounded observations only.
- Backend 1/2/4-worker measurements use synthetic marker adapters; genuine scanner timings
  are separate small local samples. No production capacity or availability is inferred.
- Restore and retention commands fail closed and preserve uncertain or referenced data.
  Backups remain private and depend on a trusted manifest receipt and retained software/assets.
